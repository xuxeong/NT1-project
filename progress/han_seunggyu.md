## [2026-11-25] 기존 서버 기능의 요청·응답 및 동작 처리 보완

### 주요 작업 내용

1. **배차·제어 요청 검증 및 오류 처리 보완**
   * 목적지 누락, 위도·경도 일부 누락, 좌표와 정류장 ID 혼용을 422로 거절.
   * 전원 제어에 JSON true/false만 허용하고 빈 제어 요청을 거절.
   * 존재하지 않는 차량과 제어 불가능 상태를 404/409로 구분하고 경로 계산 오류 처리 보완.

2. **차량 상태와 제어 동작 통일**
   * 운행 상태 `operation_state`, 작업 상태 `task_status`, 주행 모드 `driving_mode`를 구분하여 제공.
   * 고장·전원·연결·운영 상태에 따른 배차 및 주행 재개 조건 통일.
   * 진행 중·일시정지 작업 덮어쓰기 방지 및 완료 작업의 일시정지·재개 차단.
   * 기존 연동 명세 3.2에 맞춰 주행 중에만 일시정지, 일시정지 중에만 재개하도록 제한. 이미 일시정지한 작업의 pause 및 주행 중 resume은 409로 처리.
   * 고장 신고 시 즉시 정차하고 해제 후에는 별도 요청으로 재개하도록 처리.
   * 주행 중 전원 OFF를 거절하고 정차 후 OFF는 작업 취소로 반영. 완료·취소 결과는 다음 배차까지 유지.

3. **차량 상세 정보 및 연동 명세 보완**
   * 차량 조회 REST API·WebSocket·학생 앱 API의 배터리 기반 예상 주행거리 계산 통일.
   * 전원·연결 상태에 따른 센서 표시 가능 여부 `sensors_available` 추가.
   * 주행 중 현재 위치 문자열 갱신 및 차량 정보 필드의 단위·의미 정리.
   * 앱–서버 연동 명세에 요청·응답 예시, 상태값, 제어 조건, 오류 처리와 필드 대응표 추가.
   * 중복된 제어 설명을 기존 2~5장에 통합하고 6장은 새 차량 조회 필드로 정리.

4. **제외 기능인 도어·조명 제어 제거**
   * 대시보드의 도어·전조등 버튼과 제어 JavaScript 제거.

## [2026-11-19] 제공 API 명세서 반영 및 지도 좌표 배차·차량 선택 기능 구현

* **담당 역할**: Mock 서버 REST API, 인증, 가상 차량 상태 관리 및 관제 대시보드 구현

### 주요 작업 내용

1. **제공 API 명세서 기반 REST API 구현 (`app/api/neolix.py`, `app/models/neolix.py`)**
   * 원본 `API_명세서.docx`의 API 경로, HTTP 메서드, Query·JSON Body 위치 및 필드 대소문자를 대조하고 반영.
   * 차량 목록·차량 상태·지점 목록·현재 작업·계획 경로·작업 취소·전원 제어·상태 일괄 조회 API 구현.
   * 차량 조회·취소의 `vin`과 지점 목록의 `Vin`을 구분하고 요청·응답의 문자열·숫자·배열 형식 반영.
   * 기존 정류장 기반 배차 코드는 호환용으로 유지하되, 기본 정류장 목록은 빈 배열로 제공.

2. **토큰 발급 및 공통 인증 검증 구현**
   * `GET /auth/oauth/token`에서 `client_id`, `client_secret`, `grant_type`을 받아 시험용 토큰 발급.
   * `MOCK_APP_ID`, `MOCK_APP_SECRET` 환경변수로 인증값을 설정하고 토큰 유효기간을 3,600초로 관리.
   * 공통 Query인 `signature`, `timeStamp`, `nonce`, `access_token`의 필수 입력 및 형식 검증.
   * 명세서 Java 예제와 동일하게 Secret·타임스탬프·nonce를 문자열 사전순 정렬 후 연결하고 UTF-8 SHA-1 소문자 16진수로 서명 계산.
   * `X-From`은 필수이며 빈 값·공백만 있는 값을 거절. `X-Version`은 숫자 `A.B.C` 형식을 검사하고 생략 시 기본값 `0.0.0` 적용.

3. **도로망 기반 목적지 보정 및 좌표 주행 구현 (`app/simulator/`)**
   * OpenStreetMap의 C-Track 도로 데이터를 사용해 선택 좌표를 가장 가까운 도로 선분 위로 보정.
   * 도로 노드 사이의 중간 지점도 목적지로 선택할 수 있도록 선분 투영 방식 적용.
   * 차량 현재 위치부터 목적지까지 일방통행 방향을 지키는 경로 계산.
   * 호출 확정 시 계산한 경유점을 시뮬레이터에 저장하고 해당 경로를 따라 가상 차량 이동.
   * 도착 후 다음 배차는 차량의 현재 좌표에서 이어지도록 처리.

4. **지도 좌표 배차와 명세의 작업 API 연결**
   * 대시보드의 좌표 배차를 `getCurrentMission`, `getPlanningRoute`, `vehicleCancel`로 조회·제어할 수 있도록 연결.
   * 고정 정류장을 추가하지 않고 작업별 출발·도착 좌표와 작업 전용 임시 ID 사용.
   * 작업 상태를 주행 중 `1`, 일시정지 `2`, 완료 `3`, 취소 `4`로 구분.
   * 호출 확정 당시의 전체 실제 주행 경로를 계획 경로 응답에 반영하고, 완료·취소 후에는 빈 경로 목록 반환.
   * Mock 전용 일시정지·재개 API를 연결하고 대시보드 비상 정지 결과도 작업 조회에 취소로 반영.

5. **지도 중앙 핀 기반 목적지 선택 UI 구현 (`app/templates/dashboard.html`)**
   * 지도 중앙에 선택 핀을 고정하고 지도를 드래그하여 목적지를 선택하는 방식으로 변경.
   * 지도 이동 중에는 도로 보정·경로 미리보기만 갱신하고, 호출 버튼을 눌러야 배차를 확정하도록 분리.
   * 미리보기 경로는 파란색, 확정 주행 경로는 보라색으로 표시.
   * 확정 경로 끝에 흰 테두리의 보라색 목적지 포인트 추가.
   * 주행 중 목적지 선택을 숨기고, 정차한 대기·일시정지·완료 상태에서만 선택 허용.
   * 이전 요청 취소와 응답 버전 검사로 오래된 미리보기 결과가 최신 선택을 덮어쓰지 않도록 처리.

6. **차량 클릭에 따른 호차 선택 및 제어 대상 전환**
   * 전체 차량 목록을 기반으로 지도에 1·2호차 마커를 함께 표시.
   * 차량 마커 클릭 시 선택 호차를 변경하고 노란 테두리로 구분.
   * 차량 이름·위치·속도·배터리·작업·센서 상태를 선택 차량 기준으로 갱신.
   * 배차·일시정지·재개·비상 정지·도어·조명 제어를 선택 차량에 연결.
   * 차량 전환 시 이전 미리보기를 초기화하고 현재 페이지에서 확정한 경로·목적지를 차량별로 관리.

7. **임의 순환 코스 제거 및 차량 정보 보완**
   * 기업 제공 공식 코스가 아닌 임의 코스 `r1`~`r5`와 코스 선택·반복 주행 UI 제거.
   * OSM 도로망과 지도 좌표 배차는 유지하고 `/api/routes`는 빈 목록 반환.
   * LiDAR·레이더·카메라·IMU·GNSS 상태 및 시스템 온도 등을 시험용 데이터로 구성.
   * 제공 이미지의 N3(X3) 적재 용량·최대 적재중량·배터리·만충 주행거리·충전 시간·방수 등급·자율주행 수준을 차량 제원에 반영.
   * 차량 제원의 최대 설계속도와 가상 주행속도를 구분하고 시뮬레이터 주행속도는 15km/h 유지.

8. **Swagger 문서 및 자동화 테스트 보완**
   * 토큰·차량·작업·경로·성공·오류 응답 모델을 추가하여 상세 응답 구조 표시.
   * API별 한국어 설명, 인증 규칙, 작업 상태 코드, 좌표 배차 연동 및 기존 정류장 배차의 제약사항 문서화.
   * 좌표 보정·일방통행·도착 후 다음 배차·작업 상태 전환·인증 Query·X 헤더 검증 테스트 작성.
   * 최신 전체 테스트 16개 통과. 이전 29개에서 임의 코스 전용 테스트 13개 제외.
   * 차량 선택 JavaScript 문법 및 모의 UI 검사 통과.
   * 임시 Uvicorn 기동 후 `/docs`, `/openapi.json`, `/dashboard`, `/api/routes` 정상 응답 확인.

### 기술적 고민 및 해결

* **정류장 기반 명세와 좌표 배차 연결**: 원본 요청 형식은 유지하면서 좌표 배차의 출발·도착 정보를 작업 전용 임시 ID로 표현하여 기존 작업 조회·경로·취소 API에 연결.
* **미리보기와 실제 주행 분리**: 지도 이동이 차량 명령으로 이어지지 않도록 미리보기와 배차를 구분하고 호출 시점의 확정 경로를 실제 주행에 사용.
